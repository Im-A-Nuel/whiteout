# Whiteout

**A blizzard roguelike where the chain can't see you die.**

Whiteout is a fog-of-war survival game on Zama's FHEVM. You walk an 8x8 snowfield with a hidden map of pits and treasure. Your position, your moves, the map, and whether you are still alive all stay encrypted onchain. Every transaction looks identical to an observer. The only thing the chain ever reveals is the final result, with proof, at the end of the run.

Built for the **Zama Developer Program Mainnet Season 5: Confidential Gaming**. Deployed on Sepolia.

## Why this game cannot exist on a transparent chain

Take any onchain Minesweeper or "mines" game. The moment you click a cell, everyone sees the cell, and everyone sees the explosion. A death is a disclosure: it tells the world where a hazard is, and the next player copies it.

Whiteout makes **dying a private event**.

| What | Transparent chain | Whiteout (FHEVM) |
| --- | --- | --- |
| Hazard map | Must be revealed or committed to a trusted party | Generated by onchain encrypted RNG, never decrypted until the run ends |
| Your position | Public after every move | Encrypted bitboard, only you can decrypt it |
| Your moves | Public calldata | Encrypted input, indistinguishable from any other move |
| Death | Public the instant it happens | An encrypted flag, even the contract cannot read it |
| Score | Public as you earn it | Computed under encryption, decrypted once with a KMS proof |
| Fairness | "Trust the server RNG" | Map is fixed at `startRun`, revealed in full at the end, anyone can replay the run |

If the state were public, the game would collapse into a lookup table. That is the confidentiality design.

## How to play

1. Connect a wallet on Sepolia and press **Start run**. The contract rolls a fresh encrypted map.
2. You stand in the **cabin** (top-left). You have **24 steps** before the storm closes in.
3. Move with the arrow keys or the on-screen D-pad. Each step costs one transaction.
4. After every step you get two private signals, visible only to you:
   - **Cold** means at least one pit is next to you.
   - **Glint** means at least one treasure is next to you.
5. Walk onto a treasure to pick it up. Walk onto a pit and you die, silently.
6. Get back to the cabin and press **Finish**. Your score is the treasure you carried home. Die, or finish away from the cabin, and the score is zero.
7. On finish, the fog lifts: the whole map and your exact path are revealed, and anyone can replay the run.

## Tech overview

- **Contracts:** Solidity 0.8.27, `@fhevm/solidity` 0.11, Foundry with `forge-fhevm` for tests.
- **Encrypted types used:** `euint64` bitboards (hazards, treasure, position, path), `euint8` (direction input, treasure count, score), `ebool` (alive, signals).
- **Zama primitives used:** encrypted inputs with proofs, onchain encrypted RNG (`randEuint64`), ACL (`allowThis` / `allow`), user decryption (relayer SDK), public decryption with `makePubliclyDecryptable` + `checkSignatures`.
- **Frontend:** Next.js (App Router), TypeScript, ethers v6, `@zama-fhe/relayer-sdk` loaded client-side only.
- **Network:** Sepolia.

## Judging criteria map

| Zama criterion | Where Whiteout answers it |
| --- | --- |
| Gameplay and UX | Deduction under a clock, rules explained in ten seconds, a "chain view vs your view" panel, full replay |
| Confidentiality design | Position, moves, map, and death are all encrypted. Public state is limited to the step counter |
| Would the game break if state were public? | Yes: public death leaks the hazard map, public position leaks your strategy |
| Fairness | Map from onchain RNG fixed before the first move, fully revealed with proof at the end, replayable from the revealed path |
| Functionality on Sepolia | One complete run, start to finalize, is playable by a single wallet with no opponent |
| Code quality | Bitboard engine is isolated and unit-tested against a plaintext reference model, see [`TEST_PLAN.md`](./TEST_PLAN.md) |
| Demo quality | 3-minute script in [`DEMO_AND_SUBMISSION.md`](./DEMO_AND_SUBMISSION.md) |

## Run locally

Contract commands run in WSL (`wsl -d Ubuntu-ext`), where Foundry is installed.

```bash
# contract: build and test on forge-fhevm, no network needed
cd contract
forge soldeer install
forge test

# contract: deploy to Sepolia (details in contract/README.md)
cast wallet import deployer --interactive
export SEPOLIA_RPC_URL=...  ETHERSCAN_API_KEY=...
forge script script/DeployWhiteout.s.sol --rpc-url sepolia --account deployer --broadcast --verify

# scripted full run on Sepolia with the relayer: encrypt, step, decrypt, finish, finalize, with timings
cd backend && npm install
SEPOLIA_RPC_URL=... WHITEOUT_ADDRESS=0x... PRIVATE_KEY=0x... npm run smoke:sepolia -- 8

# frontend: set NEXT_PUBLIC_WHITEOUT_ADDRESS in frontend/.env.local after deploying
cd frontend && npm install && npm run dev
# /practice plays offline, /demo previews the chain screens with a simulated driver

# balance simulator
cd backend && npm run sim
```
